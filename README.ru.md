# CallNotify

[中文](README.md) · [English](README.en.md) · **Русский**

Превращает один HTTP-запрос в **настоящий входящий звонок** на телефоне: системный интерфейс звонка, системный рингтон, запись в журнале вызовов. При ответе текст зачитывается через TTS.

Для случаев, когда уведомление легко пропустить: упавшая сборка, завершённое обучение модели, алерты мониторинга, дежурство, забытый cron.

- **Сервер**: один исполняемый файл на Go (со встроенной отладочной консолью); есть версия на Node.js для быстрых правок
- **Клиент**: Android (Kotlin + Compose). Регистрирует телефонный аккаунт `CAPABILITY_CALL_PROVIDER`, поэтому звонок показывает **системальный телефон**, своего интерфейса звонка нет
- **Отправитель**: что угодно, что умеет HTTP — достаточно одного `curl`

## Как это работает

```
ваш скрипт / CI / мониторинг
      │  POST /api/v1/notify   X-API-Key: cn_xxx
      ▼
  сервер CallNotify  ── WebSocket ──►  Android-приложение
      ▲                                   ├─ Telecom поднимает звонок (системный UI + рингтон)
      └──────── отчёты о статусе ─────────└─ после ответа: TTS читает текст → автозавершение
```

## Быстрый старт

### 1. Запуск сервера

```bash
# Windows
callnotify-server-windows-amd64.exe -port 8787
# Linux
chmod +x callnotify-server-linux-amd64 && ./callnotify-server-linux-amd64 -port 8787
```

В консоли появятся адреса, а в браузере открывается **отладочная консоль** — тестовое уведомление можно отправить без кода.

Версия на Node: `cd server && npm install && node server.js`

> Обе реализации говорят на **одном протоколе** и используют одинаковый `data.json`, поэтому взаимозаменяемы.

### 2. Сборка / установка приложения

```bash
cd android
./gradlew assembleRelease       # app-release.apk (без ключа — app-release-unsigned.apk)
./gradlew assembleDebug         # app-debug.apk, к имени пакета добавляется .debug
```

В Windows: `powershell -ExecutionPolicy Bypass -File .\build-apk.ps1`
(скрипт подставляет ASCII-путь: компилятор Kotlin не принимает не-ASCII пути.)

### 3. Настройка телефона

Откройте приложение → введите `192.168.1.10:8787` → нажмите **Зарегистрировать устройство** → скопируйте **API-ключ**.

В блоке «Готовность» четыре пункта; нажмите кнопку у того, что не зелёный:

| Пункт | Зачем |
| --- | --- |
| Разрешение на уведомления | уведомление foreground-сервиса |
| Игнорировать оптимизацию батареи | иначе процесс замораживается при выключенном экране |
| Телефонный аккаунт включён | без этого звонок не появится |
| Автозапуск / работа в фоне | требуется на многих китайских прошивках |

### 4. Отправка уведомления

```bash
curl -X POST http://127.0.0.1:8787/api/v1/notify \
  -H "Content-Type: application/json" \
  -H "X-API-Key: cn_ваш_ключ" \
  -d '{"callerName":"Сборка","callerNumber":"13800138000","text":"Сборка упала, смотрите лог","speakTimes":2}'
```

## Параметры сервера

Флаги и переменные окружения равнозначны:

| Флаг | Переменная | По умолчанию | Описание |
| --- | --- | --- | --- |
| `-port` | `PORT` | `8787` | порт |
| `-host` | `HOST` | `0.0.0.0` | адрес прослушивания |
| `-data` | `DATA_FILE` | `data.json` рядом с бинарником | хранилище устройств |
| `-offline-retention` | `OFFLINE_RETENTION` | `0` (никогда не удалять) | удалять устройство после стольких секунд офлайна. **>0 приведёт к 401 и смене ключа у «протухших» устройств** |
| `-queue-retention` | `QUEUE_RETENTION` | `10m` | сколько хранить недоставленные уведомления |
| `-notify-retention` | `NOTIFY_RETENTION` | `30m` | сколько хранить завершённые уведомления |
| `-queue-max` | `QUEUE_MAX` | `20` | размер офлайн-очереди на устройство |

## HTTP API

Авторизация: `X-API-Key: cn_xxx` или `Authorization: Bearer cn_xxx`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/api/v1/notify` | **основной эндпоинт**, достаточно ключа |
| `GET` | `/api/v1/notify/{id}` | статус уведомления |
| `GET` | `/api/v1/me` | информация об устройстве по ключу |
| `POST` | `/api/v1/devices` | регистрация устройства |
| `GET` | `/api/v1/devices/{deviceId}` | данные устройства |
| `POST` | `/api/v1/devices/{deviceId}/key` | ротация ключа |
| `POST` | `/api/v1/devices/{deviceId}/notify` | отправка по id устройства |
| `GET` | `/health` | проверка живости |
| `GET` | `/api/v1/diag` | устройства, последние 20 уведомлений, подсказки |

### Тело запроса

| Поле | Тип | Обязательно | По умолчанию | Диапазон |
| --- | --- | --- | --- | --- |
| `text` | string | нет\* | `""` | ≤2000 символов |
| `callerName` | string | нет\* | `Неизвестный` | ≤40 символов |
| `callerNumber` | string | нет | `10086` | ≤32 символов |
| `delaySeconds` | int | нет | `0` | 0–3600 |
| `ringSeconds` | int | нет | `60` | 10–300 |
| `speakTimes` | int | нет | `1` | 1–5 |

\* нужен хотя бы один из `text` / `callerName`, иначе `400`.

### Статусы

```
queued → sent → delivered → ringing → answered → completed
                          ├→ rejected / missed
                          ├→ failed (причина в note)
                          └→ expired (таймаут очереди)
```

### Ошибки

`202` принято · `400` некорректный JSON · `401` неверный ключ · `404` не найдено · `429` превышен лимит (30/мин на устройство).

Тело запроса может быть в UTF-8; если байты не являются корректным UTF-8, они декодируются как **GBK** (поведение curl в Windows).

## Настройки клиента

| Настройка | По умолчанию | Описание |
| --- | --- | --- |
| Адрес сервера | пусто | сохраняется после регистрации; смена адреса перерегистрирует устройство |
| Повторов озвучивания | 1 | 1–5 |
| Таймаут звонка | 45 с | 10–300 с |
| Динамик при ответе | вкл | маршрут полностью отдан Telecom, совпадает с переключателем в системном UI |
| Автозавершение | вкл | иначе завершать вручную |
| Агрессивное поддержание | вкл | heartbeat через `setAlarmClock` (иконка будильника в статус-баре) |

### Настройка без рук

- **Accessibility-автоконфигурация**: нажимает «Разрешить» в системных диалогах и включает переключатели телефонного аккаунта и автозапуска;
- `tools/setup-adb.ps1`: одна команда по USB выдаёт разрешения, добавляет в белый список батареи и включает accessibility;
- **Deep link**: `callnotify://setup?server=...&deviceId=...&key=...` для массового развёртывания.

## Поддержание соединения

На Android нет «никогда не падает», есть «быстро возвращается»:

| Уровень | Интервал | Зачем |
| --- | --- | --- |
| Foreground-сервис (`specialUse`) | постоянно | не упирается в 6-часовой лимит |
| Heartbeat приложения | отправка 10 с / таймаут 20 с | ловит «полуживой» сокет |
| Переподключение | от 0.3 с, максимум 15 с | быстрый возврат при мигании сети |
| `onTaskRemoved` | 0.3 / 1.5 / 5 с | перезапуск после смахивания из списка задач |
| AlarmClock | 5 мин | без разрешений, работает в Doze |
| persisted Job | 15 мин | живёт после убийства процесса и перезагрузки |

В логах различаются `соединение потеряно`, `соединение зависло` и `процесс заморожен системой`.

## Совместимость

| Случай | Комментарий |
| --- | --- |
| Вход в телефонные аккаунты | AOSP: Настройки → Звонки → Аккаунты. OnePlus/OPPO скрывают его; приложение пробует `com.android.server.telecom/.settings.EnableAccountPreferenceActivity`, иначе предлагает adb-команду |
| Имя звонящего | MIUI и подобные берут имя из контактов и игнорируют `setCallerDisplayName`; используйте номер из контактов |
| Движок TTS | Android 11+ требует `<queries>` для `TTS_SERVICE` (уже объявлено) |
| iOS | Эквивалентного API нет. Единственный путь — CallKit + VoIP push (платный аккаунт разработчика и сертификат) |

## Разработка

```bash
cd server-go && go build ./...                # Go 1.23+
cd server && npm install && node server.js    # Node 16+
cd android && ./gradlew assembleRelease
cd server && node tools/e2e-test.js http://127.0.0.1:8787   # 18 проверок протокола
```

`versionCode` увеличивается при каждом изменении, `versionName` — по semver; артефакты называются `CallNotify-<versionName>-<buildType>.apk`.

## Безопасность

- Разворачивайте за HTTPS; приложение само меняет `https://` на `wss://`
- `X-API-Key` — это пароль: не коммитьте и не публикуйте его
- Сервер не хранит тексты уведомлений; в `data.json` только имена устройств и ключи

## Ограничения

- Зависит от механизма телефонных аккаунтов Telecom; если прошивка отклоняет `addNewIncomingCall`, приложение может лишь показать причину
- Китайские прошивки замораживают фон — нужен ручной белый список, кодом это не обойти
- Нет дедупликации: два вызова — два звонка
- Состояние в памяти одного процесса: история уведомлений теряется при перезапуске (ключи устройств сохраняются)
